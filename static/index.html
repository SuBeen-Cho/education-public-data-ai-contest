LLM 자동 규칙 생성기

현재 검증 규칙(룰셋)은 사람이 매뉴얼을 읽고 Python을 직접 작성합니다. 이 기능은 담당자가 자연어로 질문하면 LLM이 검증 규칙을 자동 생성하고, 샌드박스에서 실행하여 결과까지 보여줍니다.

현재: 수동 BR 진단
법규 읽기→ 자연어 정의→ SQL 3개 작성→ 수동 실행
소요: 수일, 3명 협업, 대부분 용역 외주
제안: LLM 자동 생성
자연어 입력→ AI Rule Card→ 샌드박스→ 채택/수정
소요: 수 분, 1명, 도구 내장
학술 근거: LLM-DQR(Journal of Biomedical Informatics, 2025) — LLM 기반 DQ 규칙 자동 생성이 수동 전문가 대비 더 높은 커버리지를 달성. 3단계: 표준화 입력 → CoT 프롬프트 → 폐쇄 루프 검증(샌드박스 + 반복 디버깅).

체험해 보기 예시 데이터 기반

구현 기획

1
입력 전처리 — DB 스키마(컬럼명+타입) + 자연어 질문 + 샘플 데이터 5행을 LLM 프롬프트에 포함
AI
Rule Card 생성 — Chain-of-Thought 프롬프트로 LLM이 규칙명·대상 컬럼·조건·Python 코드·유사 기존 룰·추천 검토 우선도를 JSON으로 출력
3
샌드박스 실행 — safe_executor.py로 생성된 코드를 실행 (화이트리스트 + 5초 타임아웃 + df 읽기 전용)
4
결과 표시 + 검증 — 탐지 건수, 탐지 학교 목록, 기존 룰과 중복 여부를 자동 확인
5
채택/수정/폐기 — 담당자가 결과를 확인하고 룰셋에 저장하거나 조건을 수정

이상 전파 추적

하나의 입력 값이 잘못되면, 파생 지표와 연쇄 룰이 동시에 탐지됩니다. 이 기능은 원인 값 하나를 꼬집어 "이것 때문에 나머지가 걸린 것입니다"라고 안내하고, 원인을 확인하면 전파된 탐지가 일괄 해소됩니다.

왜 필요한가

담당자가 "왜 갑자기 3건이나 나오지?"라는 혼란을 겪을 때, 3건이 사실은 같은 원인에서 파생된 것임을 보여줍니다. 원인 1개만 확인하면 나머지가 자동 해소되어 검토 부담이 대폭 줄어듭니다.

산업 근거: 1,000+ 데이터 파이프라인 분석 결과 72%의 DQ 이슈가 비즈니스에 영향을 미친 후 발견(Datachecks 2024). 마이크로서비스 오류 전파 추적 특허(US 11,010,235)에서 "원인 → 전파 체인 → 영향 범위" 시각화 접근을 차용.

교육 데이터의 의존성 그래프

아래는 우리 룰셋에서 컬럼 간 의존 관계를 정리한 것입니다. 하나의 값이 잘못되면 화살표 방향으로 전파됩니다.

학생수
→
학급당학생수, 교원1인당학생수, 학생수변동률, C1-1, C1-3, C1-8, B1-1, C5-1
학급수
→
학급당학생수, 학급수변동률, C1-1, C1-2, C1-8, D2-2
교원수
→
교원1인당학생수, 교원수변동률, C1-3, B1-1, F1'-1
급식비총액
→
1인당급식비, 급식비변동률, C2-3, C2-3+, D2-2
학폭심의건수
→
B1-6, C3-3A/B (피해학생수 경유)
학급당학생수
→
C1-8, D2-2 (파생값이 2개 룰에 영향)

* 한 컬럼이 잘못되면 화살표 끝의 모든 지표/룰이 연쇄 영향을 받음

구현 기획

1
의존성 그래프 구축 — 룰 엔진의 각 룰이 어떤 컬럼을 입력받는지 매핑. 파생 컬럼(학급당학생수 = 학생수/학급수)의 원본 컬럼 추적
2
탐지 결과 역추적 — 동일 학교에서 여러 룰이 동시 탐지되면, 공통 원인 컬럼을 BFS(너비 우선 탐색)로 탐색
AI
원인 설명 생성 — LLM이 전파 경로를 자연어로 요약. "학급수 하나 때문에 3개 룰이 연쇄 탐지되었습니다"
4
일괄 해소 기능 — 원인 노드 "정상 확인" 클릭 시, 해당 노드에 의존하는 모든 하위 탐지를 자동으로 "정상 처리". 검토 우선도도 재계산
5
우선 확인 순서 안내 — 가장 많은 하위 탐지에 영향을 미치는 원인 노드를 1순위로 표시
