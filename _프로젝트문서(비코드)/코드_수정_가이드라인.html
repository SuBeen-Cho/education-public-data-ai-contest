1. C5-1: 진급 시 학생 이탈

핵심 문제

정의서는 "1학년에서 2학년으로 진급할 때 몇 명이 빠지는가"를 보라고 했다. 그런데 코드는 "학교 전체 학생수가 전년 대비 몇 퍼센트 변했는가"를 보고 있다. 완전히 다른 것을 측정하고 있다.

정의서 원문

"t년 1학년에서 t+1년 2학년으로의 학년 진급 인원 변동이 -7%~+3% 범위 밖"
사용 컬럼: 학사_학생_성별학생수__1학년(남) + 1학년(여) 합산

정의서가 의도한 것 (쉬운 말로)

2024년 1학년이 272명이었는데, 그 학생들이 2025년 2학년이 되면서 241명이 됐다면, 31명(-11.4%)이 빠진 것이다. 보통 전학이나 자퇴로 1~3%만 빠지는데, 11%나 빠졌으니 뭔가 특이한 일이 있었을 수 있다. 이런 패턴을 잡으라는 것이다.

코드가 실제로 하는 것

student_count_yoy (전체 학생수 전년 대비 변동률)를 가져와서 -7% 미만이거나 +3% 초과이면 탐지한다. 이것은 "학교 전체 학생이 얼마나 변했는가"이지, "1학년이 2학년 되면서 얼마나 빠졌는가"가 아니다.

# rule_engine.py 214~223행 (_check_c5_1) def _check_c5_1(self): if "student_count_yoy" not in self.df.columns: return for _, row in self.df.dropna(subset=["student_count_yoy"]).iterrows(): chg = row["student_count_yoy"] # <-- 전체 학생수 YoY if chg < -7 or chg > 3: # <-- 정의서와 같은 임계값이지만 self._add(row, "C5-1", ...) # 측정 대상이 완전히 다름
문제

측정 대상 자체가 다르다. 전체 학생수 YoY가 -7%~+3% 안이더라도 학년별로는 -11%가 빠질 수 있고, 반대로 전체 학생수가 -8% 이더라도 학년 진급은 정상(-2%)일 수 있다.

현재 코드의 C5-1은 사실상 B1-1(학생수 급변동)과 중복된다. 정의서가 의도한 "학년 진급 추적"은 전혀 구현되어 있지 않다.

코드 수정 가이드

data_loader.py에서 학년별 학생수 컬럼을 로드해야 한다. 현재 SCHOOL_COLS에 학년별 성별학생수 컬럼이 없으므로 추가가 필요하다.

수정 후 동작

2024년 1학년 272명 -> 2025년 2학년 241명일 때, 변동률 = (241-272)/272 = -11.4%.
-11.4%는 -7% 미만이므로 탐지된다. 정의서가 예시로 든 용화여고(-11.4%), 서울문영여고(-8.7%) 등이 정확히 잡힌다.

2. B1-1: 학생 교원 급변동

핵심 문제

정의서의 B1-1은 "10% 이상 변동 + 직전 2년 평균 대비 3배"라는 이중 조건이다. 코드는 10% 이상 변동만 체크한다. 이것은 정의서의 B1-2(단년 10% 이상)와 같은 로직이다. 즉, 코드에서 B1-1이라고 쓰여 있지만 실제로는 B1-2를 수행하고 있다.

정의서 원문

B1-1: "전년 10% 이상 변동이면서 직전 2년 평균 대비 변동 폭이 3배 이상"
대상: 학생수, 학급수, 교원수 (3개 항목)
B1-2: "전년 대비 10% 이상 변동" (3년 시계열 없을 때의 단순 버전)

정의서가 의도한 것 (쉬운 말로)

B1-1은 "갑자기 이상하게 튄 해"를 잡는 것이다. 예를 들어:

  • 2023년 교원 80명, 2024년 82명(+2.5%), 2025년 93명(+13.4%) -- 이전 2년간 2명 변동이었는데 갑자기 11명 변동 = 5.5배. 10% 이상이면서 3배 이상이므로 B1-1에 해당.
  • 반면 매년 10%씩 계속 변하고 있었다면 "갑자기 튄 것"이 아니라 추세이므로 B1-1에 해당하지 않는다.

B1-2는 3년 데이터가 없을 때(2023년 데이터만 있을 때) 단순히 10% 초과만 보는 간단한 버전이다.

코드가 실제로 하는 것
# rule_engine.py 136~145행 (_check_b1_1) def _check_b1_1(self): for col, name in [("student_count_yoy", "학생수"), ("teacher_count_yoy", "교원수")]: # <-- 학급수 없음! if col not in self.df.columns: continue for _, row in self.df.dropna(subset=[col]).iterrows(): yoy = row[col] if abs(yoy) >= 10: # <-- 단순 10% 초과만 체크 self._add(row, "B1-1", ...) # "2년 평균 대비 3배" 없음
문제
  1. "2년 평균 대비 3배" 조건이 완전히 빠져 있다. 현재 코드는 매년 10% 이상 변동하면 전부 잡는다. 정의서의 의도는 "평소와 다르게 갑자기 튄 해"만 잡는 것이다.
  2. 학급수(class_count_yoy)가 대상에서 빠져 있다. 정의서는 학생수, 학급수, 교원수 3개 항목 모두를 대상으로 한다.
  3. B1-2와 구분이 없다. 현재 B1-1 코드가 사실상 B1-2 로직이다.
코드 수정 가이드
# rule_engine.py: _check_b1_1 전체 교체 def _check_b1_1(self): """B1-1: 10% 이상 + 직전 2년 평균 대비 3배 (3년 시계열 필요) B1-2: 10% 이상 (단년, 시계열 부족 시)""" targets = [ ("student_count", "학생수"), ("class_count", "학급수"), # 학급수 추가 ("teacher_count", "교원수"), ] df_sorted = self.df.sort_values(["school_code", "year"]) for school_code, group in df_sorted.groupby("school_code"): if len(group) < 2: continue group = group.sort_values("year") for col, name in targets: if col not in group.columns: continue vals = group[col].values years = group["year"].values for i in range(1, len(vals)): if pd.isna(vals[i]) or pd.isna(vals[i-1]) or vals[i-1] == 0: continue yoy = (vals[i] - vals[i-1]) / vals[i-1] * 100 if abs(yoy) < 10: continue # 3년 시계열이 있으면 B1-1 조건 체크 if i >= 2 and not pd.isna(vals[i-2]): prev_diff = abs(vals[i-1] - vals[i-2]) curr_diff = abs(vals[i] - vals[i-1]) # 이전 변동이 0이면 비율 계산 불가 -> B1-2로 처리 if prev_diff > 0: ratio = curr_diff / prev_diff if ratio >= 3.0: self._add(group.iloc[i], "B1-1", f"{name} 급변동", 2, "B1", f"{name} {yoy:+.1f}% " f"(이전변동 대비 {ratio:.1f}배)", {"field": name, "yoy": round(yoy,1), "ratio": round(ratio,1)}) continue # B1-1로 잡힌 건은 B1-2 생략 # B1-2: 시계열 부족이거나 3배 미만 self._add(group.iloc[i], "B1-2", f"{name} 급변동 (단년)", 2, "B1", f"{name} 전년대비 {yoy:+.1f}%", {"field": name, "yoy": round(yoy, 1)})
수정 후 동작

예: 교원수 80 -> 82 -> 93인 학교.
- 2024->2025 YoY = +13.4% (10% 이상 통과)
- 이전 변동 = |82-80| = 2, 현재 변동 = |93-82| = 11, ratio = 5.5 (3배 이상 통과)
- B1-1로 탐지. "이전 변동 대비 5.5배"라는 맥락 정보도 함께 제공된다.

반면 매년 교원수가 10%씩 꾸준히 변하는 학교(70 -> 77 -> 85)는:
- ratio = 8/7 = 1.1 (3배 미만)
- B1-1이 아닌 B1-2(단년)로만 탐지된다.

3. C1-3: 학생↔교원 불균형

핵심 문제

임계값이 다르고(3% vs 5%), 절대값 조건이 빠져 있고(5명 이상), 교원수 기준이 다르다(강사 포함 vs 강사 제외). 세 가지가 동시에 어긋나 있다.

정의서 원문

"학생수 변동 5% 이내인데 교원수(강사 제외) 변동 10% 이상 또는 5명 이상"

정의서가 의도한 것 (쉬운 말로)

학생수는 별로 안 변했는데 교원수만 확 바뀐 경우를 잡는다. 예를 들어 학생수가 2% 줄고 교원수가 15% 줄었다면, "학생은 비슷한데 선생님이 갑자기 많이 줄었다"는 뜻이다.

교원수는 "강사를 제외한 교원수"를 사용해야 한다. 학교알리미의 자격종별 총계에는 강사가 포함되어 있어서, 강사가 바뀌면 교원수가 바뀐 것처럼 보이기 때문이다.

"5명 이상"이라는 절대값 조건도 있다. 교원이 20명인 작은 학교에서 2명(10%) 바뀌는 건 정상이지만, 30명인 학교에서 6명(20%) 바뀌는 건 큰 변화다. 이를 구분하기 위해 절대값 기준도 함께 본다.

코드가 실제로 하는 것
# rule_engine.py 111~117행 (_check_c1_3) def _check_c1_3(self): for _, row in self.df.dropna( subset=["student_count_yoy", "teacher_count_yoy"] # <-- 강사 포함 교원수 ).iterrows(): s, t = row["student_count_yoy"], row["teacher_count_yoy"] if abs(s) < 3 and abs(t) >= 10: # <-- 3%와 10%만 체크 self._add(row, "C1-3", ...)

문제 세 가지:

  1. 학생수 임계값이 3%이다. 정의서는 5%이다. 3%면 범위가 좁아서 탐지 건수가 줄어든다.
  2. "또는 5명 이상" 절대조건이 없다. 비율이 10% 미만이어도 절대 변동이 5명 이상이면 잡아야 한다.
  3. teacher_count_yoy는 강사 포함 교원수 기준이다. data_loader.py에서 teacher_count는 교원_자격종별교원현황__계(강사 포함)를 사용한다. 정의서는 "강사 제외" 기준을 요구한다.
코드 수정 가이드

1단계: data_loader.py에 강사 제외 교원수 YoY 추가

# data_loader.py calculate_derived() 함수 안에 추가 # 강사 제외 교원수 전년 대비 변동률 (C1-3, C1-4에서 사용) if "teacher_count_no_instructor" in df.columns: df["teacher_no_inst_yoy"] = ( df.groupby("school_code")["teacher_count_no_instructor"] .pct_change() * 100 )

2단계: rule_engine.py 수정

# rule_engine.py: _check_c1_3 전체 교체 def _check_c1_3(self): """C1-3: 학생수 5% 이내 + 교원수(강사 제외) 10% 이상 또는 5명 이상""" t_yoy_col = "teacher_no_inst_yoy" # 강사 제외 교원수 YoY t_abs_col = "teacher_count_no_instructor" # 강사 제외 교원수 절대값 if t_yoy_col not in self.df.columns: return df_sorted = self.df.sort_values(["school_code", "year"]) for school_code, group in df_sorted.groupby("school_code"): if len(group) < 2: continue for i in range(1, len(group)): curr = group.iloc[i] prev = group.iloc[i - 1] s = curr.get("student_count_yoy", np.nan) t = curr.get(t_yoy_col, np.nan) if pd.isna(s) or pd.isna(t): continue t_curr = curr.get(t_abs_col, np.nan) t_prev = prev.get(t_abs_col, np.nan) t_diff = abs(t_curr - t_prev) if ( pd.notna(t_curr) and pd.notna(t_prev) ) else 0 # 조건: 학생수 5% 이내 + (교원수 10% 이상 또는 5명 이상) if abs(s) <= 5 and (abs(t) >= 10 or t_diff >= 5): self._add(curr, "C1-3", "학생↔교원 불균형", 2, "C1", f"학생수 {s:+.1f}%(안정) " f"교원수(강사제외) {t:+.1f}% ({int(t_diff)}명 변동)", {"student_yoy": round(s, 1), "teacher_yoy": round(t, 1), "teacher_diff": int(t_diff)})
수정 후 동작

예: 학생수 -1.2%(안정), 교원수(강사 제외) 72 -> 66명(-8.3%, 6명 변동)
- abs(-1.2) <= 5 -- 통과
- abs(-8.3) < 10이지만, t_diff = 6 >= 5 -- "또는 5명 이상" 조건으로 통과
- 기존 코드에서는 미탐지였으나, 수정 후에는 탐지된다.

부분 불일치

정의서와 부분적으로 다른 4건

아래 항목들은 기본 로직은 맞지만, 일부 조건이 빠져 있거나 세부 수치가 다르다. 탐지 결과에 영향은 있지만, 불일치보다는 영향 범위가 작다.

1. C3-3: 미조치 피해 (등급A/B)

차이점 2가지

(1) 등급A 조건에서 "가해학생 선도조치 >0" 확인이 빠져 있다. (2) "동일 학교 3학기 이상 반복이면 등급A로 승격"하는 로직이 없다.

정의서 원문

등급A: "피해학생 3명 이상 + 보호조치 0건 + 가해학생 선도조치 >0, 또는 동일 학교 3회 이상 반복"
등급B: "피해학생 1~2명 + 보호조치 0건, 또는 동일 학교 2회 반복"

코드가 실제로 하는 것

등급 구분은 피해학생수만 본다 (v >= 3이면 A, 아니면 B). 선도조치 유무를 확인하지 않는다. 반복 승격 로직도 없다.

# rule_engine.py 119~133행 (_check_c3_3) # 현재 코드의 등급 판정: star = 3 if v >= 3 else 2 # 피해학생수만으로 판정 grade = "A" if v >= 3 else "B" # 선도조치 확인 없음 # 3학기 반복 승격 로직 없음
코드 수정 가이드
# rule_engine.py: _check_c3_3에 선도조치 조건 추가 def _check_c3_3(self): # 1차 탐지: 행 단위 school_flags = {} # {school_code: [grade_list]} for _, row in self.df.iterrows(): v = int(row.get("bullying_victims", 0) or 0) p = int(row.get("bullying_protection", 0) or 0) perp = int(row.get("bullying_perpetrators", 0) or 0) if v > 0 and p == 0: if perp == 0: continue # 등급X # 등급A: 피해 3명 이상 + 가해학생 존재(선도조치 수행 추정) if v >= 3 and perp > 0: grade, star = "A", 3 else: grade, star = "B", 2 self._add(row, f"C3-3{grade}", "미조치 피해", star, "C3", ...) # 반복 추적 sc = str(row.get("school_code", "")) school_flags.setdefault(sc, []).append(grade) # 2차: 3학기 이상 반복이면 등급A로 승격 for sc, grades in school_flags.items(): ab_count = sum(1 for g in grades if g in ("A", "B")) if ab_count >= 3: # 해당 학교의 B등급 탐지를 A등급으로 변경 for d in self.detections: if d.school_code == sc and d.rule_id == "C3-3B": d.rule_id = "C3-3A" d.star = 3

참고: 현재 데이터에서 bullying_perpetrators는 가해학생수이다. 정의서의 "선도조치 건수"와는 다르지만, data_loader.py에 선도조치 건수 컬럼이 없으므로, 가해학생수 > 0을 대용으로 사용할 수 있다. 정밀하게 하려면 BULLY_COLS에 선도조치 건수 컬럼을 추가해야 한다.

2. B1-5: 진학률 급변동

별 등급 불일치

정의서 명세의 Python 코드는 20%p 이상이면 ★★★, 15~20%p면 ★★로 구분한다. 그런데 rule_engine.py는 15%p 이상이면 전부 ★★★으로 처리한다. 또한 정의서 본문 표에서는 B1-5를 일괄 ★★로 적어두었다.

정의서 Python 명세
# 정의서 부록 Python 코드 (948~949행) if abs(diff) >= 15.0: star = 3 if abs(diff) >= 20.0 else 2 # 20%p 이상이면 ★★★
rule_engine.py 코드
# rule_engine.py 173~176행 diff = rates[i] - rates[i - 1] if abs(diff) >= 15: self._add(..., "B1-5", "진학률 급변동", 3, ...) # 항상 ★★★
코드 수정 가이드

정의서 본문 표는 ★★이고, 정의서 Python 명세는 ★★/★★★ 구분이다. 정의서 본문 표를 우선으로 하되, Python 명세의 20%p 구분도 살려서 다음과 같이 수정:

# ★ 등급 분리 적용 star = 3 if abs(diff) >= 20 else 2 self._add(group.iloc[i], "B1-5", "진학률 급변동", star, "B1", ...)

3. D2-2: 유사학교 대비 극단값

"중앙값 대비 50% 이상" 조건 누락

정의서는 "중앙값 대비 50% 이상 또는 IQR 1.5배 외부"라고 되어 있지만, 코드는 IQR 1.5배만 체크한다.

정의서 원문

"중앙값 대비 50% 이상 또는 IQR 1.5배 외부"

코드가 실제로 하는 것

IQR 1.5배 바깥에 있는 학교만 탐지한다. 중앙값 대비 50% 조건은 구현되어 있지 않다.

코드 수정 가이드
# _check_d2_2에 중앙값 50% 조건 추가 median = yr[col].median() for _, row in yr.iterrows(): v = row[col] is_iqr_outlier = (v < lo) or (v > hi) is_median_outlier = abs(v - median) / median >= 0.5 if median > 0 else False if is_iqr_outlier or is_median_outlier: self._add(row, "D2-2", ...)

참고: 실제로 IQR 1.5배 바깥에 있는 값은 대부분 중앙값 50%도 충족하므로, 탐지 결과에 큰 차이는 없을 수 있다. 하지만 정의서와의 일관성을 위해 추가하는 것이 맞다.

4. E2-2: 3년 동일값 반복

노이즈 필터가 불완전하고 대상 컬럼이 제한적

정의서의 "소규모 정수 1~5 제외" 필터가 코드에서는 {0, 1, 100}만 제외한다. 또한 정의서는 "블랙리스트 외 모든 수치 컬럼"을 대상으로 하지만, 코드는 5개 컬럼만 체크한다.

정의서 노이즈 필터

  • 상수 값 {0, 1, 100} 제외

추가 발견

코드 전반에 걸친 참고사항

1. run_all() 주석의 용어

rule_engine.py 42행에 self._check_c5_1() # 코호트 단절이라는 주석이 있다. 프로젝트 용어 규칙에 따르면 "코호트 단절" 대신 "진급 시 학생 이탈"을 사용해야 한다. 같은 라인에서 43행의 self._check_e2_2() # 3년 정체도 "3년 동일값 반복"으로 수정해야 한다.

2. Detection 클래스의 category 필드

Detection 데이터클래스의 category 필드는 프로젝트 용어 규칙에 따르면 "대분류"라고 불러야 한다. 필드명 자체를 바꾸면 외부 연동에 영향이 있으므로, 주석이나 문서에서 "대분류"로 표기하는 것을 권장한다.

3. B1-1의 ★ 등급 확인

코드에서 B1-1의 star는 2로 되어 있어 정의서와 일치한다. 다만 MEMORY.md에 "B1-4: ★★→★★★ 복원"이라는 메모가 있다. 현재 코드에 B1-4는 미구현이므로, 구현 시 ★★★으로 설정해야 한다.

4. D2-2의 유사학교 범위

현재 _check_d2_2는 연도별로 전체 42교를 대상으로 IQR을 계산한다(구 구분 없음). 정의서 5.3절에서 "서울 3구 통합 일반고 42교 (구 단위 분석은 N<20으로 통계 의미 없어 통합)"라고 명시하고 있으므로, 현재 코드의 전체 비교 방식이 정의서와 일치한다.
